# VANGUARD TEAM – نسخه ۲ (Foundation)

## محتویات
- رابط فارسی راست‌چین، واکنش‌گرا و قابل نصب (PWA)
- ورود مدیر با Firebase Authentication (Email/Password)
- بررسی نقش مدیر از `users/{uid}` پیش از نمایش پنل
- مدیریت اعضا، شاخص‌های داشبورد، نمایش ساده ساختار درختی
- وظایف، چک‌لیست ۱۶ مرحله‌ای، گزارش پایه و پشتیبان JSON
- لوگوی ارسالی VANGUARD TEAM در assets

## انتشار در GitHub Pages
1. در مخزن GitHub یک شاخه جدید به نام `v2-foundation` بسازید (از `main`).
2. فایل‌های این بسته را در ریشه شاخه آپلود کنید؛ پوشه `assets` نیز حفظ شود.
3. GitHub → Settings → Pages → Deploy from a branch را باز کنید و شاخه `v2-foundation` و پوشه `/ (root)` را انتخاب کنید.
4. پس از انتشار، آدرس شاخه Pages را باز کنید. در صورت نیاز در Pages تنظیم کنید تا نسخه فعلی `main` تغییر نکند.

## پیش‌نیاز Firebase
پروژه Firebase از قبل در `app.js` پیکربندی شده است.
- Authentication → Email/Password باید فعال باشد.
- حساب مدیر باید از قبل ساخته شده باشد.
- سند `users/{UID}` باید شامل `role: "admin"` و `active: true` باشد.
- Firestore collections: `users`, `members`, `tasks`, `growth` (سه مجموعه آخر با اولین ذخیره ساخته می‌شوند).

## امنیت – مهم
قوانین فعلی admin-only را فعلاً تغییر ندهید. این نسخه فقط برای ورود و استفاده حساب مدیر اصلی طراحی شده است. نقش سرشاخه در فرم صرفاً یک فیلد مدیریتی برای دسته‌بندی است و به هیچ‌کس دسترسی Firebase نمی‌دهد.
برای ورود اعضا، دعوت‌نامه، دسترسی شاخه‌ای و انتصاب سرشاخه‌ها باید در مرحله بعد قوانین Firestore و ترجیحاً منطق سمت سرور طراحی و آزمایش شود. هرگز قوانین عمومی مانند `allow read, write: if true` قرار ندهید.

## محدودیت نسخه پایه
- درخت تیم در حال حاضر فقط یک سطح از زیرمجموعه‌ها را نشان می‌دهد.
- گزارش‌ها فعلاً شمارنده‌های پایه هستند.
- جلسات، حضور و غیاب، اعلان‌های خودکار و مقایسه سرشاخه‌ها در مرحله بعد اضافه می‌شوند.
- Firebase SDK از CDN رسمی بارگذاری می‌شود؛ برای اولین ورود اینترنت لازم است.
